# Choose your learning path


## Start from the work you want to do

You do not need thirty-two subscriptions to understand this ecosystem. Read [Foundations](foundations.md), choose one hands-on tool in each relevant layer, and use the alternatives to build judgment. Every tool has its own substantial chapter. The time estimates below are planning estimates for reading and optional practice, not vendor promises.

| Your goal | Start with | Then explore | Useful outcome |
| --- | --- | --- | --- |
| Deliver software with coding agents | Codex or Claude Code | Cursor, Copilot, Devin | One accepted, reproducible change |
| Coordinate a queue of agent work | Paradev, then Factory | OpenHands and the change notes | A small task queue with explicit review |
| Build an agent platform | E2B or Daytona | Modal, Cloudflare, CodeSandbox, Freestyle | An isolated job with exported artifacts |
| Operate developer workspaces | GitHub Codespaces | Coder | A documented, reproducible remote setup |
| Launch a voice product quickly | Vapi or Retell | ElevenAgents and Twilio | A synthetic support conversation |
| Build a custom voice stack | LiveKit or Pipecat | Realtime, Deepgram | A turn-aware tool-using conversation |
| Produce release videos | Runway or Google video tools | Kling and Luma | A coherent short sequence |
| Make training presenters | HeyGen or Synthesia | Tavus and D-ID | A reviewed, captioned explainer |

## The focused survey: two weeks

Spend roughly twelve to eighteen hours on a selective first pass. Read Foundations, the category overviews, and Compare & Choose. Choose one coding agent and complete a small local task. Read one sandbox guide and trace its lifecycle with the offline example. Choose one voice platform and simulate a tool-backed conversation. Storyboard a thirty-second release video and compare a footage tool with an avatar tool.

The survey's deliverable is a decision memo: which tools you would trial for your actual work, what you still need to verify, and which tools add no useful capability to your current workflow. This is orientation, not completion of all thirty-two hands-on chapters.

## The complete curriculum: sixteen weeks

Budget roughly eight to twelve hours weekly if you complete most optional applications, with extra time for unfamiliar infrastructure. Read two tool chapters per week and compare them on the same kind of task. Account setup and paid experiments can change the pace. You can complete the conceptual and offline work without activating every service.

## A project that connects the course

Use the fictional ReleaseDesk product throughout. Coding tools improve the release-note workflow. Sandboxes run its checks in isolated environments. Voice tools explain a release using a synthetic knowledge fixture. Video tools turn the approved explanation into a short training asset. Keep the approved release facts identical across modalities so you can spot invented claims.

You can complete the course with separate small projects instead. Continuity is useful because it reduces domain-learning overhead; it is not a requirement to build a large integrated platform. The [project page](projects.md) offers scoped deliverables and acceptance checks.

## Decide how deep to go in each chapter

For a tool you may adopt, follow setup, the worked example, troubleshooting, and the optional application. For an alternative you only need to evaluate, read the mental model, operating workflow, tradeoffs, and verification boundary. Mark account-specific claims for later trial. Reading a guide and executing a paid workflow are different levels of evidence.

Each chapter includes a prompt or brief you can adapt. These are reusable requests, not proof that a tool was run. Keep the first trial small enough that you can independently judge it. Increase autonomy only when you understand the environment and have a reliable review method.

## Revisit current changes before spending

Check the [research date and lifecycle notes](watchlist.md) before installing packages or buying access. Especially review retired Sora API routes, Google's video API transitions, HeyGen's current API version, Runloop's wind-down, OpenHands' current architecture, and Vibe Kanban's hosted-service sunset. The curriculum teaches maintained entry points where evidence supports them and labels uncertainty where it does not.
